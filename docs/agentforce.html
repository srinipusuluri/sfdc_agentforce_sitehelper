What Agentforce is for

Agentforce handles conversations. Someone types a request in their own words, and an agent decides what to do: answer, collect details, run an action on Salesforce data, or hand the person to a human. Use it when the input is free text and the right response depends on what was said.

Meant for

  • Open questions from website visitors about the company and products
  • Guided capture, such as a demo or callback request
  • Answering routine questions before they reach staff, which is the deflection
  • Staff lookups and small updates in plain language
  • Handing a person to a human with the conversation attached

Not meant for

  • Sending notifications nobody asked for. Use Slackforce.
  • Fixed rules that never vary. Use a Flow or a trigger.
  • Statements where a wrong answer costs money, such as prices or guarantees. The Site Helper script forbids them.
  • Letting anonymous visitors change records

Architecture

A visitor opens the chat on the site. The Embedded Messaging deployment starts a messaging session on the channel, and the channel's session handler passes that session to the Site_Helper agent. The agent's router picks one of four subagents. Only the Escalation subagent leaves the agent: it calls @utils.escalate, and Omni-Channel routes the session to the fallback queue where a human accepts it in the Service Console.

Omni-Flow router, as an option. This org routes straight to the agent and uses a single queue, so no routing flow is needed. An Omni-Flow router becomes useful when you want a decision before the agent (business hours, language, VIP customers) or a choice of several queues or skills after escalation. The org already ships standard routing flows such as MsgRouting. The switch is on the channel: set the routing type to Omni-Flow and select a flow with a Route Work action that targets the agent first and a queue second. Nothing in the agent script changes.

What Agentforce agents add

A chatbot follows a fixed script. An Agentforce agent reasons about each message, chooses from the topics and actions you gave it, runs them against live Salesforce data, and hands off to a person when it should. This project uses most of these pieces. The table says which.

Case Triage Assistant, the internal agent

Built and tested

A second, separate agent for support staff. It lists open Cases and changes a Case's priority. It reads and writes Case data, so it should not face the public. It shows how to give an agent Apex actions.

  1. Apex classes

    Two @InvocableMethod classes. Reads use WITH USER_MODE. The write action validates the priority and the case number.

  2. Agent action definitions

    Each class is wrapped by a GenAiFunction. The folder must contain input/schema.json and output/schema.json. Without them the action cannot be used and the agent falls into Off Topic.

  3. Topic

    The GenAiPlugin topic lists the two actions and holds the instructions. The write action asks for confirmation.

  4. Bot user access

    A permission set gives the bot user the two classes and Case read/edit. The Einstein Agent license rejects View All permissions.

/**
 * Agentforce action: list open (non-closed) Cases, optionally filtered by priority.
 * Runs in user mode so the agent only sees what the running user can see.
 */
public with sharing class CaseTriageListInvocable {
    private static final Integer MAX_ROWS = 10;

    public class Request {
        @InvocableVariable(label='Priority' description='Optional: High, Medium or Low. Leave blank for all open cases.')
        public String priority;
    }

    public class Result {
        @InvocableVariable(label='Summary' description='Human-readable list of the matching open cases')
        public String summary;
        @InvocableVariable(label='Case Count')
        public Integer caseCount;
    }

    @InvocableMethod(
        label='List Open Cases'
        description='Returns up to 10 open cases (newest first), optionally filtered by priority.'
        category='Case Triage'
    )
    public static List<Result> listOpenCases(List<Request> requests) {
        List<Result> results = new List<Result>();
        for (Request req : requests) {
            String prio = String.isBlank(req.priority) ? null : req.priority.trim();
            List<Case> cases;
            if (prio == null) {
                cases = [
                    SELECT CaseNumber, Subject, Status, Priority, Account.Name
                    FROM Case
                    WHERE IsClosed = FALSE
                    WITH USER_MODE
                    ORDER BY CreatedDate DESC
                    LIMIT :MAX_ROWS
                ];
            } else {
                cases = [
                    SELECT CaseNumber, Subject, Status, Priority, Account.Name
                    FROM Case
                    WHERE IsClosed = FALSE AND Priority = :prio
                    WITH USER_MODE
                    ORDER BY CreatedDate DESC
                    LIMIT :MAX_ROWS
                ];
            }
            List<String> lines = new List<String>();
            for (Case c : cases) {
                lines.add(
                    c.CaseNumber + ' | ' + c.Priority + ' | ' + c.Status + ' | ' +
                    (c.Account.Name == null ? 'No account' : c.Account.Name) + ' | ' + c.Subject
                );
            }
            Result r = new Result();
            r.caseCount = cases.size();
            r.summary = cases.isEmpty() ? 'No open cases found.' : String.join(lines, '\n');
            results.add(r);
        }
        return results;
    }
}

/**
 * Agentforce action: change the Priority of a Case identified by its case number.
 */
public with sharing class CaseTriageEscalateInvocable {
    public class Request {
        @InvocableVariable(label='Case Number' description='The case number, e.g. 00001002' required=true)
        public String caseNumber;
        @InvocableVariable(label='New Priority' description='High, Medium or Low' required=true)
        public String newPriority;
    }

    public class Result {
        @InvocableVariable(label='Message' description='Outcome of the update')
        public String message;
    }

    @InvocableMethod(
        label='Set Case Priority'
        description='Sets the priority of a case (High, Medium or Low) using its case number.'
        category='Case Triage'
    )
    public static List<Result> setPriority(List<Request> requests) {
        List<Result> results = new List<Result>();
        for (Request req : requests) {
            Result r = new Result();
            try {
                if (req.newPriority == null || !new Set<String>{ 'High', 'Medium', 'Low' }.contains(req.newPriority)) {
                    r.message = 'Priority must be High, Medium or Low.';
                } else {
                    List<Case> found = [
                        SELECT Id, Priority FROM Case WHERE CaseNumber = :req.caseNumber WITH USER_MODE LIMIT 1
                    ];
                    if (found.isEmpty()) {
                        r.message = 'Case ' + req.caseNumber + ' was not found.';
                    } else {
                        String old = found[0].Priority;
                        found[0].Priority = req.newPriority;
                        update as user found;
                        r.message = 'Case ' + req.caseNumber + ' priority changed from ' + old + ' to ' + req.newPriority + '.';
                    }
                }
            } catch (Exception e) {
                r.message = 'Could not update case: ' + e.getMessage();
            }
            results.add(r);
        }
        return results;
    }
}

Slack alerts

Live, tested end to end

A trigger posts to Slack when a High priority Case is created, and a scheduled job posts a daily digest. Both go through one class that reads the webhook URL from the custom label Slack_Webhook_Url. While the label says REPLACE_ME, nothing is sent.

force-app/main/default/classes/SlackCaseNotifier.cls66 lines
/**
 * Posts Case summaries to Slack through an incoming webhook.
 * The webhook URL lives in the protected custom label Slack_Webhook_Url.
 * While the label still says REPLACE_ME, nothing is sent.
 */
public with sharing class SlackCaseNotifier {
    @TestVisible
    private static String webhookOverride;

    private static String webhookUrl() {
        String url = webhookOverride != null ? webhookOverride : Label.Slack_Webhook_Url;
        return (String.isBlank(url) || url == 'REPLACE_ME') ? null : url;
    }

    public static String buildDigest() {
        List<AggregateResult> rows = [
            SELECT Priority p, COUNT(Id) n FROM Case WHERE IsClosed = FALSE GROUP BY Priority
        ];
        Map<String, Integer> counts = new Map<String, Integer>{ 'High' => 0, 'Medium' => 0, 'Low' => 0 };
        for (AggregateResult r : rows) {
            counts.put((String) r.get('p'), (Integer) r.get('n'));
        }
        return ':clipboard: *Daily case digest*\n' +
            ':red_circle: High: ' + counts.get('High') + '\n' +
            ':large_orange_circle: Medium: ' + counts.get('Medium') + '\n' +
            ':large_green_circle: Low: ' + counts.get('Low');
    }

    public static String buildAlert(List<Case> cases) {
        List<String> lines = new List<String>();
        for (Case c : cases) {
            lines.add('• ' + c.CaseNumber + ' - ' + c.Subject);
        }
        return ':rotating_light: *New High priority case(s)*\n' + String.join(lines, '\n');
    }

    public static void send(String text) {
        String url = webhookUrl();
        if (url == null) {
            return;
        }
        HttpRequest req = new HttpRequest();
        req.setEndpoint(url);
        req.setMethod('POST');
        req.setHeader('Content-Type', 'application/json');
        req.setBody(JSON.serialize(new Map<String, String>{ 'text' => text }));
        new Http().send(req);
    }

    @future(callout=true)
    public static void sendAsync(String text) {
        send(text);
    }

    public static void alertHighPriority(List<Case> cases) {
        List<Case> high = new List<Case>();
        for (Case c : cases) {
            if (c.Priority == 'High') {
                high.add(c);
            }
        }
        if (!high.isEmpty() && webhookUrl() != null && !System.isFuture() && !System.isBatch()) {
            sendAsync(buildAlert(high));
        }
    }
}
